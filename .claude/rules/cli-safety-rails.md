# CLI安全装置ルール

エージェントのハルシネーションによるデータ損失を防ぐ。変更操作は必ずドライランを経由すべき。

## 必須実装

### ドライラン

- 全ての変更操作（作成・更新・削除）に `--dry-run` フラグを実装する
- ドライランはリクエストをローカルでバリデーションし、実際のAPI呼び出しを行わない
- ドライラン結果は「何が実行されるか」をJSON形式で出力する

```bash
# 使用例
mycli files delete --file-id abc123 --dry-run
# → { "action": "delete", "resource": "files/abc123", "validated": true }
```

### レスポンスサニタイズ

- 外部APIレスポンスにプロンプトインジェクションが含まれる可能性を考慮する
- レスポンスをサニタイズしてからエージェントに返す
- 悪意あるメール本文やドキュメント内容がエージェントの指示を上書きすることを防ぐ

### 確認フロー

- 破壊的操作（削除・上書き）はデフォルトで確認プロンプトを表示する
- `--force` や `--yes` で確認をスキップ可能にするが、エージェント向けスキルファイルでは「常にdry-runを先に実行する」ことを指示する
