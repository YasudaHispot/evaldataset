# CLI設計原則（常時ロード）

CLIを設計・実装する際の根本原則。全ファイルに適用。

> **注意**: `.claude/rules/cli-*.md` 内のコマンド例に登場する `mycli` は汎用プレースホルダである。
> プロジェクト固有のコマンド名に書き換えてはならない。原則の適用時に読み替えること。

## 根本思想

> Human DX optimizes for discoverability and forgiveness.
> Agent DX optimizes for predictability and defense-in-depth.

エージェントは信頼できるオペレータではない。公開WebAPIと同等の防御レベルで構築する。

## 実装ロードマップ（優先順位順）

CLIを新規作成、または既存CLIを改修する場合、以下の順で段階的に適用する:

1. **`--output json`** を追加して機械可読出力を提供する
2. **入力バリデーション** を実装する（制御文字拒否、パストラバーサル防止、クエリパラメータ埋め込み拒否）
3. **`schema` / `--describe`** コマンドでランタイムスキーマ自己記述を追加する
4. **`--fields`** でフィールドマスクによるコンテキストウィンドウ保護を実装する
5. **`--dry-run`** で変更操作のバリデーションを実装する
6. **CONTEXT.md / スキルファイル** で暗黙の不変条件を明文化する
7. **MCPサーフェス** をAPIラッパーCLIに提供する

## 設計チェックリスト

CLI実装時に以下を確認する:

- [ ] `--output json` が全コマンドで動作するか
- [ ] stdoutがTTYでない場合にJSON出力になるか
- [ ] エラー出力もJSON形式か（jsonモード時）
- [ ] exitコードが一貫しているか
- [ ] 全テキスト入力で制御文字を拒否しているか
- [ ] ファイルパスがCWDにサンドボックスされているか
- [ ] 変更操作に `--dry-run` があるか
- [ ] `--fields` でレスポンスを制限できるか
- [ ] 認証が環境変数で設定可能か
- [ ] エージェント向けスキルファイル/CONTEXT.mdが存在するか
