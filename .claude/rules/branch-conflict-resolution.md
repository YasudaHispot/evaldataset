# ブランチ運用・コンフリクト自動解決ルール

## ブランチ運用

### ブランチ種別

| ブランチ | 命名規則 | 用途 | マージ先 |
|---------|---------|------|---------|
| main | `main` | 安定版 | - |
| research | `research/{概要}` | `/research-design` での調査・spec設計 | main |
| task | `task{n}` | `/continue-task` でのタスク実装 | main |
| fix | `fix{n}` | `/fix-issues` でのISSUE修正 | main |

### 運用フロー

```
/research-design → research/{概要} → mainにマージ
    ↓ (specがmainに入った状態)
/continue-task → task{n} → mainにマージ
```

- `/research-design` はresearchブランチで先行して実施し、mainにマージする
- `/continue-task`、`/fix-issues` はmainからブランチを切る（specが既にmainにある前提）

## コンフリクト自動解決ルール

マージ時にコンフリクトが発生した場合、以下のルールに従い自動解決する。

### docs/ 配下（設計書・spec）

| 競合パターン | 解決方法 |
|-------------|---------|
| 受入条件の追加同士 | **両方採用**（両方のGiven/When/Thenを保持） |
| 設計書本文の競合 | **main側を優先**し、ブランチ側の受入条件のみ追記 |
| 同一チェッカーの受入条件が競合 | より**網羅的な方**を採用 |

### src/ 配下（実装コード）

| 競合パターン | 解決方法 |
|-------------|---------|
| 同一関数の変更 | **ブランチ側を優先**（最新の実装意図を尊重） |
| import文の競合 | **両方採用**（重複は除去） |
| 新規ファイルの競合 | 発生しない想定（ファイル分担ルールによる） |

### tests/ 配下（テストコード）

| 競合パターン | 解決方法 |
|-------------|---------|
| テストケースの追加同士 | **両方採用** |
| フィクスチャの競合 | **ブランチ側を優先** |
| conftest.pyの競合 | **両方の変更をマージ**（重複は除去） |

### 解決後の確認

コンフリクト解決後、必ず以下を実行する:
1. `uv run pytest` でテストが通ることを確認
2. テストが失敗する場合は、失敗原因を分析して修正する
