# CLIマルチサーフェスアーキテクチャルール

単一バイナリが複数のインターフェースを提供する。共有の情報源（スキーマ定義等）から各サーフェスを生成する。

## 必須実装

### サーフェス一覧

同一CLIから以下のインターフェースを提供することを検討する:

| サーフェス | 用途 | 特徴 |
|---|---|---|
| CLI（人間向け） | 対話的ターミナル | カラー出力、プログレスバー |
| CLI（エージェント向け） | JSON出力モード | 構造化出力、exitコード |
| MCP（Model Context Protocol） | JSON-RPCツール（stdio） | シェルエスケープ不要、型付き関数呼び出し |

### MCP対応

- APIをラップするCLIはMCPサーフェスの提供を強く推奨する
- MCPはシェルエスケープ、引数パースの曖昧さ、出力パースを排除する
- JSON-RPCの型付き関数呼び出しにより、エージェントとの統合が正確になる

### 認証戦略（エージェント向け）

- 環境変数でトークン・認証情報ファイルパスを受け取る
  - 例: `MYCLI_TOKEN`, `MYCLI_CREDENTIALS_FILE`
- サービスアカウントを優先する
- ブラウザリダイレクト型OAuthフローを避ける（ヘッドレス環境で動作しない）
- `--auth-method` で認証方式を明示的に選択可能にする
